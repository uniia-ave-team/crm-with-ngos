# Контракт API

`openapi.json` — межа між `apps/api` (C#) і `apps/web` (TypeScript). Файл
генерується з коду API та комітиться: зміна ендпоінта стає видимою як diff у
pull request'і, а не як помилка в клієнті після розгортання.

## Потік

```
apps/api  ──вивантаження──>  openapi.json  ──генерація──>  apps/web/src/app/api/generated
              (комітиться, рецензується)                  (у .gitignore; створюється при npm install)
```

- Вивантаження: `Microsoft.AspNetCore.OpenApi` під час збірки API.
- Генерація клієнта: `openapi-generator-cli` з генератором `typescript-angular`
  — Angular-сервіси на `HttpClient` та типи моделей.
- `just contract` виконує обидва кроки.

CI перегенеровує специфікацію з коду і завершується з помилкою, якщо результат
відрізняється від закоміченого файлу.

## Сфера дії

Це внутрішній контракт, а не публічний API. Його єдиний споживач — вебклієнт
продукту, який виходить у тому самому релізі. Тому:

- відсутній префікс версії (`/api/v1`) та узгодження версій;
- відсутні період застарівання та гарантії сумісності між релізами;
- ламка зміна виконується одним pull request'ом, який змінює ендпоінт,
  специфікацію та місця виклику.

Якщо з'явиться другий споживач з незалежним циклом випуску — зовнішня інтеграція
або мобільний застосунок на Capacitor — потрібна буде явна політика сумісності.
Це питання зафіксоване серед відкритих рішень у
[docs/architecture/adr/README.md](../../docs/architecture/adr/README.md).

## Рецензування

У `CODEOWNERS` каталог належить обом командам: pull request, що змінює
специфікацію, потребує схвалення з кожного боку.
