Схема бази описана моделями EF Core в `Crm.Infrastructure`; міграції
лежать у `apps/api/src/Crm.Infrastructure/Migrations`.

## Створення

```bash
just migration-add AddContacts     # назва англійською, PascalCase
just migration-remove              # прибрати останню, якщо її ще не застосовано
```

Команди викликають локальний `dotnet-ef` (встановлюється `just setup`) з
`Crm.Infrastructure` як проєктом міграцій і `Crm.Api` як стартовим.

Згенеровані файли комітяться разом зі зміною моделі. Перед комітом варто
переглянути міграцію: EF Core інколи видаляє й створює колонку там, де
очікувалося перейменування.

## Застосування

Міграції застосовуються автоматично під час запуску API, після них
виконується сидинг початкових даних. Окремо запускати
`dotnet ef database update` не потрібно.

## Правила

- **Лише вперед.** Down-міграції не використовуються; помилку виправляє
  нова міграція.
- **Спершу розширити, потім звузити.** Нова колонка додається й
  заповнюється в одному релізі, стара видаляється в наступному. Так
  попередня версія API продовжує працювати з оновленою базою.
- **Не змінювати застосовані міграції.** Міграцію, яка вже є в `main`,
  не редагують і не видаляють.
