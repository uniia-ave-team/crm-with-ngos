`packages/api-contract/openapi.json` — контракт між API і вебклієнтом. Він
генерується з коду .NET і комітиться, тому кожна зміна ендпоінта видна в
diff pull request'а, а [довідник API](../../api/) на цьому сайті завжди
відповідає `main`.

```
код API ──just contract-spec──▶ openapi.json ──just contract-client──▶ Angular-клієнт
                                     │
                                     └──▶ довідник API на сайті
```

## Порядок дій

1. Змінити контролер, команду чи модель в `apps/api`. Описи операцій,
   параметрів і моделей беруться з XML-коментарів (`/// <summary>`).
2. Виконати `just contract`: оновлюються `openapi.json` і згенерований
   клієнт у `apps/web/src/app/api/generated`.
3. Оновити місця виклику у вебклієнті.
4. Закомітити `openapi.json` разом зі зміною коду. Згенерований клієнт не
   комітиться: він створюється автоматично перед `npm start`,
   `npm run build` і тестами.

Фронтенд-розробникові .NET не потрібен: клієнт будується із закоміченого
`openapi.json`.

## Що потрапляє в контракт

- Документ OpenAPI 3.1 для версії `v1`; маршрути — `/api/v1/...`
  ([рішення 0002](../../decisions/0002-api-versioning/)).
- `operationId` має вигляд `{Контролер}{Дія}`, наприклад `UsersAssignRole`.
  З нього генератор бере назву функції клієнта, тож перейменування методу
  контролера змінює назву функції.
- Тіла запитів і відповідей описані лише як `application/json`.
- Опис операції з `[HasAccessRight]` містить перелік потрібних
  [прав](../../architecture/access/).

## Як генерується

`just contract-spec` збирає `Crm.Api` з `-p:GenerateOpenApi=true`. Пакет
`Microsoft.Extensions.ApiDescription.Server` запускає застосунок в
окремому процесі й записує документ у файл. Міграції та сидинг у цьому
режимі пропускаються, тому база не потрібна. Звичайна збірка документ не
генерує.

`just contract-check` перегенеровує документ і падає, якщо він
відрізняється від закоміченого. Ця перевірка входить у `just ci` і
джобу `api` в CI.
