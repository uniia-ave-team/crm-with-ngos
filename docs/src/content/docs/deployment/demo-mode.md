Демо-режим перетворює інсталяцію на публічну демо-версію. Увійти може
будь-хто: дані для входу показані на сторінці входу. Кожен відвідувач
працює у власній копії демо-даних, тому не бачить чужих змін, а його
копія зникає після закінчення сеансу.

:::caution[Лише для окремої інсталяції]
Не вмикайте демо-режим на інсталяції зі справжніми даними. Усе, що є в
базі на момент запуску, стає відкритим для кожного відвідувача, а паролі
демо-акаунтів публічні.
:::

## Як увімкнути

Локально, разом з усім стеком:

```bash
just demo
```

Або додайте файл `compose.demo.yaml` до звичайної команди:

```bash
docker compose -f compose.yaml -f compose.demo.yaml up --build
```

У власному розгортанні достатньо однієї змінної середовища API:
`DemoMode__Enabled=true`.

## Як це працює

1. Під час запуску API застосовує міграції. Якщо база порожня, він
   наповнює її демо-даними: організація, користувачі з різними ролями й
   заповненими додатковими полями профілю, дванадцять таблиць із записами
   (донори, волонтери, бенефіціари, видача допомоги, склад, поїздки, заявки
   на гранти, витрати, партнери, заходи, навчання, звернення на гарячу
   лінію) і п'ять проєктів у «Планері» з темами, завданнями в усіх
   статусах і коментарями. Координатор і волонтер мають доступ до
   «Планера», адміністратор — до всього.
2. З цієї бази API створює шаблон. Сама база далі відкрита лише для
   читання: з неї беруться дані сторінки входу.
3. Коли відвідувач входить, API копіює шаблон в окрему базу — пісочницю.
   Її ідентифікатор записується в токен доступу, і всі подальші запити
   відвідувача йдуть у його пісочницю.
4. Пісочниця живе фіксований час від першого входу, за замовчуванням
   одну годину. Активність цей строк не продовжує. Вебклієнт показує
   зворотний відлік, а коли час спливає, повертає відвідувача на сторінку
   входу. Наступний вхід починає з чистих демо-даних.
5. Якщо відвідувач входить повторно в тому самому браузері (наприклад,
   під іншим демо-акаунтом), він продовжує в тій самій пісочниці й бачить
   свої попередні зміни.

Демо-блок на сторінці входу й банер над застосунком попереджають, що
розробка ще триває: можливі помилки, а деякі сервіси поки що можуть бути
недоступні.

Файли, які відвідувач завантажує (аватар, логотип), зберігаються в теці
його пісочниці й зникають разом з нею.

Вимкнення чи видалення колеги завершує його сеанси, а зміна його ролей
робить недійсними видані раніше токени доступу (клієнт оновлює їх і
отримує нові права). Обидва діють лише в пісочниці цього відвідувача: в
інших пісочницях той самий демо-користувач і далі працює.

Повідомлення про планові роботи (`crm notice`) записується в спільну
базу, і його бачать усі відвідувачі, зокрема ті, чиї пісочниці створено
раніше.

Журнал змін (аудит) у демо-режимі вимкнено: інакше зміни відвідувачів
лишалися б у спільній базі й після видалення їхніх пісочниць.

## Що вимкнено в демо

Дії, результат яких мав би вийти за межі сеансу, повертають помилку
`403` з кодом `DEMO_MODE_RESTRICTED`:

- запрошення колег і прийняття запрошення;
- створення токена для відновлення пароля і саме відновлення;
- створення першого адміністратора.

Усе інше працює як у звичайній інсталяції.

## Вимоги

- **Право створювати бази.** Користувач PostgreSQL, під яким працює API,
  повинен мати право `CREATEDB`. Користувач, якого створює образ
  `postgres` через `POSTGRES_USER`, його має.
- **Підключення до бази.** Кожна пісочниця має власний пул підключень.
  Підніміть `max_connections` у PostgreSQL до 200 (у `compose.demo.yaml`
  це вже зроблено).
- **База лише для демо.** Демо-дані записуються лише в порожню базу. Щоб
  оновити їх після виходу нової версії, перестворіть базу (видаліть том
  PostgreSQL) і запустіть API знову.
- **Один екземпляр API.** Список пісочниць зберігається в пам'яті
  процесу, тому запускати кілька екземплярів API з однією базою не можна.
- **Той самий домен для вебклієнта й API.** Продовження сеансу після
  повторного входу працює через cookie, тому вебклієнт і API мають бути
  доступні з однієї адреси (через зворотний проксі). Без цього демо теж
  працює, але кожен вхід починає нову пісочницю.

## Параметри

Усі параметри необов'язкові.

| Змінна                                         | Опис                                                              | За замовчуванням |
| ---------------------------------------------- | ----------------------------------------------------------------- | ---------------- |
| `DemoMode__Enabled`                            | Вмикає демо-режим                                                 | `false`          |
| `DemoMode__Sandbox__MaxSandboxes`              | Скільки пісочниць може існувати одночасно                         | `30`             |
| `DemoMode__Sandbox__LifetimeMinutes`           | Скільки хвилин живе пісочниця від моменту створення               | `60`             |
| `DemoMode__Sandbox__EvictableAfterIdleSeconds` | Після скількох секунд бездіяльності пісочницю можна достроково звільнити для нового відвідувача, коли вільних місць немає | `600` |
| `DemoMode__Sandbox__NewSandboxesPerAddress`    | Скільки нових пісочниць може створити одна IP-адреса за вікно      | `10`             |
| `DemoMode__Sandbox__NewSandboxWindowMinutes`   | Тривалість цього вікна, хвилин                                    | `10`             |
| `DemoMode__Sandbox__MaxUploadFiles`            | Скільки файлів можна завантажити в одну пісочницю                  | `20`             |
| `DemoMode__Sandbox__MaxUploadBytes`            | Сумарний розмір файлів однієї пісочниці, байтів                    | `20971520`       |
| `DemoMode__Sandbox__CleanupIntervalSeconds`    | Як часто видаляються прострочені пісочниці, секунд                 | `60`             |
| `DemoMode__Sandbox__MaxPoolSize`               | Розмір пулу підключень однієї пісочниці                            | `4`              |
| `DemoMode__DemoBlockedPaths__0`                | Додатковий шлях, запис у який заборонено (`/api/v1/...`)           | —                |

### Демо-акаунти

Без налаштувань створюються три акаунти: адміністратор, координатор і
волонтер. Власний список задається так:

| Змінна                            | Опис                                         |
| --------------------------------- | -------------------------------------------- |
| `DemoMode__Accounts__0__Name`     | Підпис кнопки входу, наприклад «Координатор» |
| `DemoMode__Accounts__0__Email`    | Пошта для входу                              |
| `DemoMode__Accounts__0__Password` | Пароль; має відповідати вимогам до паролів   |
| `DemoMode__Accounts__0__Role`     | Назва ролі; якщо такої немає, буде створена   |

Список читається лише під час наповнення порожньої бази.

## Скільки ресурсів потрібно

Одна пісочниця займає близько 10–15 МБ на диску бази й до
`MaxUploadBytes` у теці завантажень. З типовими лімітами це до 0,5 ГБ
для бази і до 0,6 ГБ для файлів.

## Відповіді API в демо-режимі

`GET /api/v1/system/status` повертає поле `demo` з демо-акаунтами й
тривалістю сеансу в хвилинах (без демо-режиму воно дорівнює `null`).
Токен доступу містить два додаткові поля: `demo_sid` (ідентифікатор
пісочниці) і `demo_exp` (час її видалення, Unix-час у секундах). Помилки
демо-режиму мають поле `errorCode`:

| Код                      | Статус | Коли                                                   |
| ------------------------ | ------ | ------------------------------------------------------ |
| `DEMO_MODE_RESTRICTED`   | 403    | Дію вимкнено в демо                                    |
| `DEMO_QUOTA_EXCEEDED`    | 403    | Досягнуто ліміту завантажень пісочниці                 |
| `DEMO_SESSION_EXPIRED`   | 401    | Пісочниці відвідувача вже немає; потрібен новий вхід   |
| `DEMO_CAPACITY_REACHED`  | 503    | Усі пісочниці зайняті активними відвідувачами          |
| `DEMO_TOO_MANY_SESSIONS` | 429    | З однієї адреси створено забагато пісочниць            |

## Безпека

- Паролі демо-акаунтів публічні за задумом: не використовуйте їх деінде.
- Запити без пісочниці не можуть змінювати базу. Це перевіряється на
  рівні підключення до бази, незалежно від коду конкретної функції.
- Обмежуйте кількість запитів до демо ще й на рівні проксі або CDN:
  кожен успішний вхід створює базу.
