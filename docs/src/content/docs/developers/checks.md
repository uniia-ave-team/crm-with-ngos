## Обов'язкові перевірки

Правила гілки `main` вимагають двох перевірок:

| Перевірка  | Workflow       | Що означає                                               |
| ---------- | -------------- | -------------------------------------------------------- |
| `ci-ok`    | `ci.yml`       | Жодна джоба CI не впала й не була скасована              |
| `pr-title` | `pr-title.yml` | Назва PR відповідає Conventional Commits                 |

## CI (`ci.yml`)

Запускається на кожен PR і на push у `main`. Джоби для частин, які PR не
змінює, пропускаються; пропущена джоба не валить `ci-ok`.

| Джоба   | Коли                                         | Що робить                                                          | Локально              |
| ------- | -------------------------------------------- | ------------------------------------------------------------------ | --------------------- |
| `api`   | змінено `apps/api`, контракт або інструменти | Форматування, збірка Release, тести; відповідність `openapi.json` коду; звіт про ламкі зміни API | `just api-ci`, `just contract-check` |
| `web`   | змінено `apps/web`, контракт або інструменти | `npm ci`, генерація клієнта, lint, тести, production-збірка        | `just web-ci`         |
| `docs`  | змінено `docs`, контракт або інструменти     | Збірка цього сайту                                                  | `just docs-build`     |
| `docker` | змінено `apps/api`, `apps/web`, контракт, `compose.yaml`, `.dockerignore` або інструменти | Збірка обох образів, запуск стеку, перевірка `/health`, вебклієнта й CORS; скидання пароля через `crm reset-password` і вхід з новим паролем; завантаження PNG-аватара й SVG-логотипа з перевіркою санітизації | `just up` |
| `trivy` | завжди                                       | Вразливі залежності та помилки конфігурації, зокрема Dockerfile    | —                     |

Зміна `justfile` або `ci.yml` запускає всі джоби.

### Якщо впала джоба `docker`

- **Збірка образу.** Відтворюється локально через `just up`. Найчастіше
  причина — новий файл, потрібний для збірки, не потрапив у контекст:
  перевірте `.dockerignore`.
- **Контейнер не став healthy або впав smoke test.** Логи контейнерів —
  на останньому кроці джоби; локально — `just logs`. Типова причина —
  нова обов'язкова опція API без значення в `appsettings.json` або в
  `compose.yaml`.
- **Впав smoke test CLI.** Крок реєструє користувача, скидає йому пароль
  через `docker compose exec -T api crm reset-password` і входить з новим
  паролем. Локально: `just up`, потім ті самі команди з кроку
  `Smoke test the admin CLI` у `ci.yml`. Типові причини — CLI не
  потрапив в образ або не читає пароль зі stdin.
- **Впав smoke test завантаження зображень.** Крок завантажує PNG-аватар і
  SVG-логотип зі скриптом, потім перевіряє, що скрипту в збереженому логотипі
  нема. Відповідь 500 на PNG у логах контейнера з `DllNotFoundException`
  означає, що в образ не потрапила нативна бібліотека SkiaSharp: версії
  `SkiaSharp` і `SkiaSharp.NativeAssets.Linux.NoDependencies` мають
  збігатися.

### Якщо впала джоба `api`

- **Форматування.** `just fmt`, закомітити зміни.
- **`openapi.json` не відповідає коду.** Змінився ендпоінт, модель або
  XML-коментар, а контракт не оновлений: `just contract`, закомітити
  `packages/api-contract/openapi.json`.
- **Збірка.** Попередження вважаються помилками (`TreatWarningsAsErrors`),
  зокрема попередження аналізаторів і NuGetAudit про вразливі пакети.

### Звіт про ламкі зміни API

У PR джоба `api` порівнює `openapi.json` з базовою гілкою
([oasdiff](https://github.com/oasdiff/oasdiff)) і пише список ламких змін
у підсумок джоби. Злиття це не блокує: вебклієнт оновлюється в тому ж PR.
Звіт нагадує перевірити, що клієнт оновлено, а назва PR позначає ламку
зміну, якщо вона торкається когось поза репозиторієм.

## Безпека

| Інструмент          | Що робить                                                               | Де результати               |
| ------------------- | ----------------------------------------------------------------------- | --------------------------- |
| CodeQL              | Статичний аналіз C#, TypeScript і самих workflow; PR у `main`, push у `main`, щопонеділка | Security → Code scanning |
| Trivy               | Вразливі npm-залежності, для яких є виправлення; помилки конфігурації   | Security → Code scanning    |
| NuGetAudit          | Вразливі NuGet-пакети, включно з транзитивними; валить збірку           | Лог збірки                  |
| Secret scanning     | Ключі й токени в коді; push protection відхиляє push із секретом        | Security → Secret scanning  |

Знахідки CodeQL і Trivy злиття не блокують. Нові знахідки, які вносить PR,
GitHub показує як анотації на вкладці змінених файлів.

## Dependabot

Щопонеділка Dependabot відкриває PR з оновленнями NuGet, npm (вебклієнт і
цей сайт), базових образів Docker, образу PostgreSQL у `compose.yaml` і
GitHub Actions. Пов'язані пакети згруповані: Angular, Ionic і Capacitor,
ASP.NET Core та EF Core, тестові пакети, інструменти lint і тестування,
базові образи Docker, усі GitHub Actions.

Мажорні версії PostgreSQL Dependabot не пропонує: нова мажорна версія не
відкриває наявний том з даними без `pg_upgrade`.

TypeScript Dependabot оновлює лише в межах патч-версій: Angular підтримує
вузький діапазон TypeScript, тож мінорні й мажорні оновлення приходять
разом з `ng update`.

PR від Dependabot проходять ті самі перевірки. Зелений PR можна вливати;
якщо CI впала, оновлення потребує змін у коді — їх вносять у ту саму гілку
або в окремий PR.
