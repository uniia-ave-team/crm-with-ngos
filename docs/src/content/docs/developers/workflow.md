## Мова

| Що                                                          | Мова       |
| ----------------------------------------------------------- | ---------- |
| Коміти, гілки, теги, назви й описи PR, коментарі в рецензіях | Англійська |
| Код, ідентифікатори, коментарі в коді, технічні логи        | Англійська |
| Документація (цей сайт, `README.md`, `CONTRIBUTING.md`)     | Українська |

## Гілки

`main` завжди придатна до релізу; напряму в неї не пушать. Робочі гілки
короткоживучі, відгалужуються від `main` і називаються
`тип/короткий-опис` англійською:

```
feat/contact-import
fix/role-permissions-cache
docs/api-versioning-adr
```

## Коміти

Формат — [Conventional Commits](https://www.conventionalcommits.org)
англійською.

| Тип        | Коли                                                |
| ---------- | --------------------------------------------------- |
| `feat`     | Нова можливість для користувача                     |
| `fix`      | Виправлення помилки                                 |
| `docs`     | Лише документація                                   |
| `refactor` | Зміна коду без зміни поведінки                      |
| `test`     | Лише тести                                          |
| `perf`     | Продуктивність                                      |
| `ci`       | Workflow GitHub Actions                             |
| `build`    | Збірка, залежності на рівні збірки                  |
| `chore`    | Інше обслуговування                                 |
| `style`    | Форматування без зміни коду                         |
| `revert`   | Відкат попереднього коміту                          |

Scope необов'язковий: `api`, `web`, `docs`, `ci`, `deps`. Scope
`deps-dev` ставить Dependabot для dev-залежностей.

```
feat(api): add CSV import for contacts
fix(web): keep pipeline filter after page reload
feat(api)!: rename Deal.amount to Deal.value
```

`!` після типу або футер `BREAKING CHANGE:` позначає зміну, яка потребує
дій від адміністратора інсталяції: міграція даних, нова обов'язкова
конфігурація.

## Pull request'и

- PR вливаються лише через **squash merge**. Назва PR стає повідомленням
  коміту в `main`, тому вона теж відповідає Conventional Commits — це
  перевіряє `pr-title`.
- Перед відкриттям: `just lint` і `just test`, або `just ci`, щоб виконати
  локально все, що виконає CI.
- Злиття можливе, коли зелені обов'язкові перевірки `ci-ok` і `pr-title`.
  Докладніше — у розділі [Перевірки](../checks/).
- Після злиття гілка видаляється автоматично.

Розмір PR — придатний для рецензії за один підхід. Велику зміну краще
розбити на послідовні PR.
