Є два способи запуску:

- **Усе в Docker** (`just up`) — база, API і вебклієнт у контейнерах, як на
  сервері. Щоб перевірити роботу разом або подивитися застосунок, не
  встановлюючи .NET і Node.js.
- **Розробка з hot reload** (`just db`, `just api`, `just web`) — у Docker
  лише база, API і вебклієнт запускаються напряму й перезапускаються
  після кожної зміни коду.

## Інструменти

| Інструмент                                                        | Версія                           | Потрібен для         |
| ----------------------------------------------------------------- | -------------------------------- | -------------------- |
| [Docker Desktop](https://www.docker.com/products/docker-desktop/) | будь-яка актуальна               | обох способів        |
| [just](https://just.systems)                                      | будь-яка актуальна               | обох способів        |
| [.NET SDK](https://dotnet.microsoft.com/download)                 | 10 (зафіксована в `global.json`) | розробки API         |
| [Node.js](https://nodejs.org)                                     | 24 (зафіксована в `.nvmrc`)      | розробки вебклієнта  |

Встановлення `just`:

```powershell
winget install Casey.Just      # Windows
```

```bash
brew install just              # macOS
```

На Windows команди `just` виконуються у Windows PowerShell; окремо
встановлювати PowerShell 7 не потрібно.

## Усе в Docker

```bash
just up       # зібрати образи з поточного коду й запустити
just logs     # логи API й вебклієнта
just down     # зупинити; дані лишаються
just reset    # зупинити й видалити базу, завантажені файли й логи
```

| Адреса                          | Що там                                     |
| ------------------------------- | ------------------------------------------ |
| [localhost:8080](http://localhost:8080) | Вебклієнт (nginx)                  |
| [localhost:5065/health](http://localhost:5065/health) | Стан API і бази      |
| `localhost:5432`                | PostgreSQL, користувач і пароль `crm`      |

`just up` щоразу перезбирає образи з робочої копії, тож після `git pull`
або власних змін достатньо запустити його ще раз. Незмінені шари беруться
з кешу Docker.

API в контейнері працює в режимі `Production`, як на сервері:

- міграції й початкові дані застосовуються під час запуску;
- CORS пропускає лише `http://localhost:8080` і `http://localhost:4200`;
- Scalar (`/scalar`) вимкнений — він є лише в режимі розробки.

Дані зберігаються в томах Docker і переживають `just down` та
перезбирання образів:

| Том           | Що в ньому                                    |
| ------------- | --------------------------------------------- |
| `db_data`     | База PostgreSQL                               |
| `api_uploads` | Завантажені файли: аватари, логотип, зображення сторінки входу |
| `api_logs`    | Файли логів API                               |
| `api_keys`    | Ключі ASP.NET Core Data Protection            |

Подивитися файли в томі: `docker compose exec api ls -R /data/uploads`.

### Змінні для Docker

Необов'язкові; задаються в терміналі перед `just up` або у файлі `.env`
у корені репозиторію (він не комітиться).

| Змінна        | За замовчуванням | Навіщо                                                             |
| ------------- | ---------------- | ------------------------------------------------------------------ |
| `CRM_HOST`    | `localhost`      | Адреса, за якою браузер відкриває застосунок; з неї складаються CORS і посилання на файли |
| `CRM_BIND`    | `127.0.0.1`      | На якому інтерфейсі слухають порти 8080 і 5065                    |
| `CRM_DB_PORT` | `5432`           | Порт бази на хості, якщо 5432 зайнятий іншим PostgreSQL           |

Відкрити застосунок з телефона в тій самій мережі (IP комп'ютера
`192.168.1.10`):

```powershell
$env:CRM_HOST = '192.168.1.10'; $env:CRM_BIND = '0.0.0.0'; just up
```

## Розробка з hot reload

### Налаштування

Один раз після клонування:

```bash
just setup
```

Команда перевіряє наявність інструментів, відновлює пакети .NET і npm (API,
вебклієнт, цей сайт), локальні інструменти .NET (`dotnet-ef`,
`reportgenerator`) і записує в
[user-secrets](https://learn.microsoft.com/aspnet/core/security/app-secrets)
проєкту `Crm.Api`:

- `ConnectionStrings:PostgreSqlConnection` — підключення до бази з
  `compose.yaml`;
- `JwtOptions:Secret` — випадковий ключ підпису JWT.

Наявні секрети не перезаписуються, тому `just setup` можна запускати
повторно, наприклад після оновлення залежностей.

### Запуск

Кожна команда — в окремому терміналі:

```bash
just db       # PostgreSQL 17 у Docker, localhost:5432
just api      # API з hot reload, http://localhost:5065
just web      # вебклієнт, http://localhost:4200
```

Під час запуску API застосовує міграції та заповнює базу початковими даними.

Вебклієнт звертається до API напряму: за замовчуванням на порт 5065 того
самого домену, з якого відкрита сторінка (`http://localhost:5065`). API в
режимі розробки дозволяє запити з будь-якого origin.

Способи можна поєднувати: frontend-розробник може запустити API й базу
через `just up`, а вебклієнт — через `just web`, без встановленого .NET.
Обидва займають порт 5065, тому `just api` і `just up` одночасно не
працюють.

### Перевірка

| Адреса                                                | Що має бути                          |
| ----------------------------------------------------- | ------------------------------------ |
| [localhost:5065/health](http://localhost:5065/health) | Статус `Healthy`, зокрема бази даних |
| [localhost:5065/scalar](http://localhost:5065/scalar) | Інтерактивна документація API        |
| [localhost:4200](http://localhost:4200)               | Вебклієнт                            |

## Типові проблеми

**Docker не відповідає.** Docker Desktop не запущений: запустіть його й
дочекайтеся статусу «Engine running».

**`address already in use` для порту 5432.** Порт зайнятий іншим PostgreSQL,
наприклад контейнером іншого проєкту. Зупиніть його або задайте
`CRM_DB_PORT=5433`. Для `just api` тоді змініть порт і в рядку підключення
в user-secrets.

**`address already in use` для порту 5065.** Запущено `just api`, а `just up`
теж хоче запустити API. Зупиніть одне з двох.

**API падає з помилкою підключення до бази.** База ще не запущена
(`just db`) або в user-secrets інший рядок підключення. Подивитися
секрети: `dotnet user-secrets list --project apps/api/src/Crm.Api`.

**Вебклієнт пише, що сервер недоступний.** API не запущений або сторінку
відкрито з адреси, якої немає в CORS. Для Docker-стеку адреса в браузері
має збігатися з `CRM_HOST`.

**Потрібна чиста база.** `just reset` видаляє контейнери разом з даними;
наступний `just db` або `just up` створить базу заново.
