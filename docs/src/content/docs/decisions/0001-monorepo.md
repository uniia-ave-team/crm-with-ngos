## Контекст

Проєкт складається з API на .NET, вебклієнта на Angular і документації.
Вебклієнт — єдиний споживач API, і їх розробляє одна невелика команда.
Зміна ендпоінта майже завжди потребує зміни клієнта.

## Рішення

- Усе зберігається в одному репозиторії: `apps/api`, `apps/web`,
  `packages/api-contract`, `docs`.
- Контракт API (`openapi.json`) генерується з коду й комітиться; клієнт
  генерується з нього під час збірки
  ([Зміна API](../../development/api-contract/)).
- Репозиторій має одну версію (SemVer) і один тег `vX.Y.Z` на реліз. API і
  вебклієнт випускаються разом.
- Команди розробки зібрані в одному `justfile`; CI викликає ті самі
  рецепти.

## Наслідки

- Зміна API, клієнта й документації — один PR, який перевіряється й
  вливається атомарно.
- Немає потреби підтримувати сумісність між версіями API і клієнта, поки
  в API немає інших споживачів.
- CI запускає лише джоби для змінених частин, щоб PR в одну частину не
  чекав на перевірку інших.
- Версія змінюється, навіть якщо реліз зачіпає лише одну частину.
