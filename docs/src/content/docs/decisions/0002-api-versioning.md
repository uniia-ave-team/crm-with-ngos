## Контекст

API вже використовує `Asp.Versioning` з версією в URL: `/api/v1/...`.
Єдиний споживач — вебклієнт з цього ж репозиторію, який випускається
разом з API ([рішення 0001](../0001-monorepo/)). У майбутньому можливі
зовнішні інтеграції.

## Рішення

- Версія API залишається в сегменті URL: `/api/v{version}/...`.
  Поточна й єдина версія — `v1`.
- Поки зовнішніх споживачів немає, ламкі зміни вносяться в `v1` разом з
  оновленням вебклієнта в тому ж PR. CI показує список ламких змін
  (`oasdiff`), але не блокує злиття.
- `v2` з'являється, лише коли ламка зміна торкається споживача, якого не
  можна оновити одночасно з API. Тоді `v1` і `v2` деякий час працюють
  паралельно.

## Наслідки

- Маршрути вже готові до появи нової версії без зміни адрес `v1`.
- Документ OpenAPI один (`v1`); з появою `v2` знадобиться окремий
  `openapi.json` для кожної версії.
- Перехід до суворої сумісності — окреме рішення, яке замінить це.
