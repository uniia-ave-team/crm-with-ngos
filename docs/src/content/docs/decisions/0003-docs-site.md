**Статус:** прийнято · **Дата:** 2026-10-02

## Контекст

Документація була розкидана по Markdown-файлах і швидко застаріла. Потрібно:
зручно редагувати її разом з кодом, мати пошук і навігацію, показувати
актуальний довідник API, генерований з коду .NET, і не утримувати для цього
сервер.

Розглядались Starlight (Astro), Docusaurus, MkDocs Material, VitePress і
DocFX.

## Рішення

- Сайт — [Starlight](https://starlight.astro.build) у папці `docs/`, з
  власним `package.json`. Мова сайту — українська.
- Довідник API — статична сторінка [Scalar](https://scalar.com), яка
  показує `packages/api-contract/openapi.json`, скопійований під час
  збірки.
- Публікація — GitHub Pages через GitHub Actions після злиття в `main`,
  якщо змінились `docs/` або контракт.

## Наслідки

- Документація змінюється в тому ж PR, що й код, і проходить ту саму
  рецензію; CI перевіряє, що сайт збирається.
- Довідник API не потребує ручного оновлення й ніколи не розходиться з
  `main`.
- Вбудований пошук (Pagefind) працює без зовнішніх сервісів.
- Репозиторій має бути публічним, щоб використовувати GitHub Pages без
  платного плану.
- Starlight — Node.js-проєкт; .NET-розробникам для локального перегляду
  потрібен Node.js, який і так потрібен для вебклієнта.
