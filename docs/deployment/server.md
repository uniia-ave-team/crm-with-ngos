# Рівень 2. Орендований сервер

Інструкція для адміністратора, який має доступ до сервера через SSH і базові
навички роботи з терміналом.

Основний спосіб — Docker Compose зі скриптами `install.sh` та `update.sh`;
саме в такій конфігурації продукт тестується перед релізом. Альтернативи для
тих, хто після початкового налаштування хоче керувати інсталяцією через
браузер: [Portainer](#portainer) і [Dokploy](#dokploy).

## Вимоги

- Linux-сервер (рекомендовано Ubuntu Server LTS) з root-доступом або `sudo`.
- Доменне ім'я з `A`-записом на IP-адресу сервера.
- Відкриті порти 22, 80 і 443.

Вимоги до ресурсів — [README.md](README.md#вимоги-до-сервера).

### Спрямування домену

Після замовлення сервера провайдер повідомляє його IP-адресу. У кабінеті
реєстратора доменів створіть запис:

| Поле        | Значення                                          |
| ----------- | ------------------------------------------------- |
| Тип         | `A`                                               |
| Ім'я / Host | `crm` (якщо CRM буде за адресою `crm.ваш-домен`)   |
| Значення    | IP-адреса сервера                                 |
| TTL         | за замовчуванням                                  |

Зміни набувають чинності протягом кількох хвилин, іноді до години. Перевірка:
`dig +short crm.ваш-домен` має повернути IP-адресу сервера.

## Docker Compose

### Крок 1. Встановити Docker

Офіційний спосіб для Ubuntu та Debian:

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker "$USER"
```

Вийдіть із сесії SSH та увійдіть знову, щоб членство в групі `docker` набуло
чинності. Перевірка:

```bash
docker compose version
```

### Крок 2. Отримати файли розгортання

```bash
git clone https://github.com/uniia-ave-team/crm-with-ngos.git
cd crm-with-ngos
git checkout v1.0.0        # актуальний номер — на сторінці релізів
cd deploy
```

### Крок 3. Встановити

```bash
./install.sh
```

Скрипт:

1. Перевіряє наявність Docker і Docker Compose.
2. Запитує доменне ім'я та електронну адресу для сертифіката.
3. Створює файл `.env`, генерує пароль бази даних і ключ підпису сесій.
4. Завантажує образи та запускає сервіси.
5. Чекає, доки всі сервіси перейдуть у справний стан.

Без інтерактивного вводу:

```bash
DOMAIN=crm.example.org ACME_EMAIL=admin@example.org ./install.sh
```

Після завершення CRM доступна за адресою `https://ваш-домен`. Сертифікат
видається під час першого запиту.

### Крок 4. Зберегти секрети

Файл `deploy/.env` містить `POSTGRES_PASSWORD` та `AUTH_SIGNING_KEY`. Скопіюйте
його в менеджер паролів або інше захищене сховище поза сервером. Без цих
значень резервну копію бази неможливо використати.

### Крок 5. Налаштувати зовнішнє зберігання копій

Автоматичні копії бази створюються щодня в томі `crm_backups`. Вони мають
регулярно копіюватися за межі сервера — [backups.md](backups.md).

### Щоденні операції

Усі команди виконуються в каталозі `deploy/`.

```bash
docker compose ps                  # стан сервісів
docker compose logs -f api         # журнал одного сервісу
docker compose logs -f             # усі журнали
docker compose restart api         # перезапуск сервісу
docker compose down                # зупинка (дані зберігаються)
docker compose up -d --wait        # запуск
```

Оновлення — `./update.sh`, див. [upgrading.md](upgrading.md).

### Типові проблеми

**Сторінка не відкривається.** Перевірте DNS (`dig +short ваш-домен` має
повернути IP сервера) і що порт 80 не зайнятий іншим вебсервером
(`sudo ss -ltnp | grep ':80 '`).

**Сертифікат не видається.** `docker compose logs caddy`. Типові причини: DNS
ще не поширився; порт 80 закритий брандмауером або провайдером; перевищено
ліміт спроб Let's Encrypt через попередні невдалі запуски — у цьому разі
зачекайте годину.

**`api` перезапускається.** `docker compose logs api`. Типові причини: невдала
міграція; пароль у `.env` не збігається з паролем, з яким створювався том бази.

**Недостатньо пам'яті.** `free -h`. На сервері з 1 ГБ додайте swap або
збільште тариф.

## Portainer

Portainer — панель керування контейнерами через браузер. Підходить, коли
початкове налаштування виконує адміністратор, а подальше супроводження —
співробітник без доступу до SSH. Використовується стандартний
`docker-compose.yml`; сертифікати видає Caddy, як і при встановленні скриптом.

### Встановлення Portainer

На сервері з Docker (крок 1 вище):

```bash
docker volume create portainer_data
docker run -d --name portainer --restart=always \
  -p 9443:9443 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v portainer_data:/data \
  portainer/portainer-ce:lts
```

Деякі провайдери пропонують шаблон сервера з уже встановленими Docker і
Portainer — [hosting-providers.md](hosting-providers.md).

Відкрийте `https://IP-адреса-сервера:9443`. Браузер попередить про недовірений
сертифікат — для панелі це очікувано. Створіть обліковий запис адміністратора
протягом кількох хвилин після запуску (інакше Portainer блокує реєстрацію і
контейнер потрібно перезапустити). Оберіть середовище `local`.

### Розгортання стеку

**Stacks** → **+ Add stack**:

| Поле                 | Значення                                              |
| -------------------- | ----------------------------------------------------- |
| Name                 | `crm`                                                 |
| Build method         | **Repository**                                        |
| Repository URL       | `https://github.com/uniia-ave-team/crm-with-ngos`     |
| Repository reference | `refs/tags/v1.0.0` — актуальний номер на [сторінці релізів](https://github.com/uniia-ave-team/crm-with-ngos/releases) |
| Compose path         | `deploy/docker-compose.yml`                           |

**Environment variables** → **Advanced mode**:

```
DOMAIN=crm.ваш-домен.org.ua
ACME_EMAIL=ваша@пошта.org.ua
CRM_VERSION=1.0.0
TZ=Europe/Kyiv
POSTGRES_DB=crm
POSTGRES_USER=crm
POSTGRES_PASSWORD=згенерований-пароль-від-32-символів
AUTH_SIGNING_KEY=інший-згенерований-пароль-від-32-символів
```

`CRM_VERSION` збігається з номером у Repository reference без літери `v`.
Секрети містять лише латинські літери й цифри та зберігаються в менеджері
паролів організації.

**Deploy the stack**. У **Containers** мають з'явитися п'ять контейнерів зі
станом `running`: `crm-caddy-1`, `crm-web-1`, `crm-api-1`, `crm-db-1`,
`crm-db-backup-1`; у `web`, `db` і `db-backup` — позначка `healthy`.

Журнали контейнера — **Containers** → контейнер → **Logs**. Оновлення —
[upgrading.md](upgrading.md#рівень-2-portainer).

Безкоштовна версія Portainer не підтримує відносні шляхи до файлів у стеках з
Git; `docker-compose.yml` продукту не має таких залежностей.

## Dokploy

Dokploy — панель із власним реверс-проксі (Traefik), яка сама видає сертифікати
та керує розгортанням із Git. Використовується окремий файл
`deploy/docker-compose.dokploy.yml` без сервісу Caddy.

Встановлення на чистий сервер з Ubuntu:

```bash
curl -sSL https://dokploy.com/install.sh | sh
```

Команда встановлює Docker і Dokploy; панель відкривається на
`http://IP-адреса-сервера:3000`. Подальші кроки збігаються з інструкцією
рівня 1: [quick-start.md](quick-start.md#крок-3-увійти-в-dokploy).

Панель Coolify працює за тим самим принципом і приймає той самий файл;
маршрути на `web` і `api` налаштовуються в її інтерфейсі.

## Перенесення на інший сервер

1. На старому сервері зробіть копію бази ([backups.md](backups.md)) і збережіть
   `deploy/.env` або значення змінних із панелі.
2. На новому: встановіть Docker, клонуйте репозиторій тієї самої версії,
   покладіть збережений `.env` у `deploy/`, виконайте
   `docker compose up -d --wait db`.
3. Відновіть копію бази, після чого `docker compose up -d --wait`.
4. Перемкніть DNS-запис на новий сервер.
