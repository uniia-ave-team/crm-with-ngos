# Розгортання

CRM постачається як набір Docker-образів і файл `docker-compose.yml`. Усі
способи розгортання зводяться до запуску цього файлу; відрізняються лише
інструменти, якими це робиться. Для панелей із власним реверс-проксі (Dokploy)
є варіант файлу без сервісу Caddy — `docker-compose.dokploy.yml`.

## Вибір способу

| Рівень | Ситуація                                                                                              | Документ                           |
| ------ | ----------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 1      | Немає досвіду роботи з серверами. Пробна інсталяція на власному комп'ютері або сервер із панеллю Dokploy; без терміналу. | [quick-start.md](quick-start.md) |
| 2      | Є навички роботи з терміналом по SSH. Орендований сервер; Docker Compose, Portainer або Dokploy.        | [server.md](server.md)             |
| 3      | Власне обладнання, мережа без публічної адреси, нестандартні конфігурації.                             | [own-hardware.md](own-hardware.md) |

Незалежно від рівня:

- [hosting-providers.md](hosting-providers.md) — вибір провайдера та розміщення даних.
- [backups.md](backups.md) — резервні копії: що зберігати, де і як відновлювати.
- [upgrading.md](upgrading.md) — оновлення до нової версії.

## Що входить до інсталяції

| Сервіс      | Призначення                                                        |
| ----------- | ------------------------------------------------------------------ |
| `caddy`     | Вхідна точка: HTTPS, автоматичні сертифікати, маршрутизація. Відсутній у варіанті для Dokploy, де цю роль виконує проксі панелі |
| `web`       | Інтерфейс користувача                                              |
| `api`       | Логіка застосунку; застосовує міграції бази при запуску            |
| `db`        | PostgreSQL 17                                                      |
| `db-backup` | Автоматичні резервні копії бази за розкладом                       |

Усі компоненти працюють у контейнерах. На сервері не потрібні .NET, Node.js чи
PostgreSQL.

## Вимоги до сервера

| Параметр           | Мінімум            | Рекомендовано              |
| ------------------ | ------------------ | -------------------------- |
| Процесор           | 1 vCPU             | 2 vCPU                     |
| Оперативна пам'ять | 2 ГБ               | 4 ГБ                       |
| Диск               | 20 ГБ SSD          | 40 ГБ SSD                  |
| ОС                 | Linux із Docker    | Ubuntu Server LTS          |
| Мережа             | Порти 80 і 443     | —                          |

Мінімальної конфігурації достатньо для організації з кількома десятками
користувачів. Панелі керування (Portainer, Dokploy) потребують додатково від
0,3 до 1 ГБ пам'яті.

## Вимоги до доменного імені

Для сервера в інтернеті потрібне доменне ім'я з `A`-записом, що вказує на його
IP-адресу. Сертифікат HTTPS видається автоматично через Let's Encrypt; для цього
порт 80 має бути доступний з інтернету навіть попри те, що CRM працює лише
через HTTPS.

Для обладнання без публічної адреси доменне ім'я не потрібне — див.
[own-hardware.md](own-hardware.md).

## Параметри інсталяції

Усі параметри задаються змінними середовища. Повний перелік із поясненнями —
[`deploy/.env.example`](../../deploy/.env.example). Обов'язкові:

| Змінна              | Значення                                                   |
| ------------------- | ---------------------------------------------------------- |
| `DOMAIN`            | Доменне ім'я або адреса, за якою відкривається CRM           |
| `ACME_EMAIL`        | Електронна адреса для повідомлень про сертифікат; не потрібна у варіанті для Dokploy |
| `CRM_VERSION`       | Версія релізу, наприклад `1.2.0`; без значення — останній реліз |
| `POSTGRES_PASSWORD` | Пароль бази даних; довільний рядок від 32 символів           |
| `AUTH_SIGNING_KEY`  | Ключ підпису сесій; довільний рядок від 32 символів          |

`POSTGRES_PASSWORD` і `AUTH_SIGNING_KEY` мають бути збережені окремо від
сервера: без них резервну копію бази неможливо використати.
