# Рівень 1. Встановлення без терміналу

Інструкція для тих, хто не працював із серверами. Усі дії виконуються в
звичних програмах — браузері, провіднику файлів, кабінеті провайдера.

Є два варіанти. Вони не виключають один одного: почати можна з першого, а коли
CRM стане потрібна щодня — перенести дані на другий
([backups.md](backups.md#на-новий-сервер)).

|                    | А. На власному комп'ютері                    | Б. На хостингу з панеллю Dokploy                    |
| ------------------ | -------------------------------------------- | --------------------------------------------------- |
| Для чого           | Ознайомитися, спробувати на реальних даних    | Постійна робота організації                          |
| Хто має доступ     | Лише користувач цього комп'ютера              | Будь-хто з посиланням і обліковим записом, звідусіль  |
| Коли працює        | Доки комп'ютер увімкнений і запущений Docker  | Цілодобово                                          |
| Вартість           | Безкоштовно                                  | Оренда сервера та домену; орієнтовно від 200 грн/міс |
| Що потрібно        | Windows 10/11 або macOS, 8 ГБ пам'яті, 10 ГБ на диску | Банківська картка для оплати хостингу         |
| Час                | 20–30 хвилин                                 | 40–60 хвилин, з яких більшість — очікування          |

---

## Варіант А. На власному комп'ютері

CRM встановлюється на ноутбук або ПК і відкривається в браузері на ньому ж.

> **Обмеження.** CRM працює лише доки увімкнений комп'ютер. Дані зберігаються
> на його диску: поломка або втрата комп'ютера без резервної копії означає
> втрату даних. Цей варіант призначений для ознайомлення й пробної роботи, а
> не для постійного використання організацією.

### Крок 1. Встановити Docker Desktop

Docker Desktop — програма, що запускає CRM на комп'ютері. Вона безкоштовна
для організацій із менш ніж 250 працівниками.

**Windows**

1. Завантажте інсталятор із [docker.com](https://www.docker.com/products/docker-desktop/)
   і запустіть його. Залиште позначку **Use WSL 2** увімкненою. Якщо система
   попросить перезавантаження — виконайте його.
2. Запустіть Docker Desktop. Прийміть умови використання. Вхід в обліковий
   запис не обов'язковий — оберіть **Continue without signing in** або
   закрийте вікно входу.
3. Дочекайтеся, поки в нижньому лівому куті вікна з'явиться **Engine running**.

Якщо з'явилося повідомлення про WSL — дотримуйтеся посилання в ньому: Windows
встановить потрібний компонент, після чого запустіть Docker Desktop знову.

**macOS**

1. Дізнайтеся тип процесора: меню Apple → **Про цей Mac**. Рядок **Чип**:
   Apple M1/M2/M3/M4 — «Apple Silicon», Intel — «Intel».
2. Завантажте відповідну версію з [docker.com](https://www.docker.com/products/docker-desktop/),
   відкрийте файл і перетягніть Docker у папку **Програми**.
3. Запустіть Docker із папки **Програми**, дозвольте запитані права.
   Дочекайтеся **Engine running** у нижньому лівому куті.

### Крок 2. Завантажити файли CRM

1. Відкрийте [сторінку релізів](https://github.com/uniia-ave-team/crm-with-ngos/releases).
2. У найновішому релізі в розділі **Assets** натисніть **Source code (zip)**.
3. Розпакуйте архів у папку з простим шляхом: `C:\CRM` на Windows або папку
   `CRM` у домашній папці на macOS. Усередині буде папка виду
   `crm-with-ngos-1.0.0`.

Ця папка — постійне місце інсталяції. Не переміщуйте й не видаляйте її: у ній
зберігаються налаштування та резервні копії.

### Крок 3. Запустити встановлення

**Windows**

1. Відкрийте папку `crm-with-ngos-1.0.0\deploy\windows`.
2. Двічі клацніть `install.cmd`. Якщо з'явиться вікно **Відкрити файл —
   попередження системи безпеки**, натисніть **Виконати**.
3. Відкриється вікно з ходом встановлення. Перше завантаження триває кілька
   хвилин.
4. Наприкінці Windows запитає, чи встановити сертифікат безпеки, — натисніть
   **Так**. Без цього браузер показуватиме попередження про з'єднання.
5. Автоматично відкриється браузер з адресою `https://localhost`.

**macOS**

1. Відкрийте папку `crm-with-ngos-1.0.0/deploy/macos`.
2. Двічі клацніть `install.command`. Якщо macOS не дозволяє відкрити файл:
   клацніть його правою кнопкою → **Відкрити**; або **Системні параметри** →
   **Конфіденційність і безпека** → **Усе одно відкрити**.
3. Відкриється Термінал з ходом встановлення. Перше завантаження триває кілька
   хвилин.
4. Наприкінці macOS запитає пароль користувача для додавання сертифіката
   безпеки — введіть його.
5. Автоматично відкриється браузер з адресою `https://localhost`.

### Крок 4. Зберегти секрети

У папці `deploy` з'явився файл `.env`. Він містить згенеровані пароль бази
даних і ключ підпису — без них резервну копію неможливо відновити. Відкрийте
файл текстовим редактором і збережіть його вміст у менеджері паролів організації.

На Windows файли, що починаються з крапки, можуть бути приховані. Увімкніть
показ прихованих файлів: **Вигляд** → **Показати** → **Приховані елементи**.

### Щоденна робота

| Дія                          | Як                                                                        |
| ---------------------------- | ------------------------------------------------------------------------- |
| Відкрити CRM                 | `https://localhost` у браузері                                             |
| Запустити після перезавантаження | Запустити Docker Desktop, потім знову двічі клацнути `install.cmd` / `install.command` |
| Зупинити                     | Закрити Docker Desktop (значок у треї → **Quit Docker Desktop**)            |
| Резервна копія               | `backup.cmd` / `backup.command` — файл копії з'явиться в папці `deploy/backups` |
| Оновити                      | `update.cmd` / `update.command`; докладніше — [upgrading.md](upgrading.md#рівень-1-власний-компютер) |

Щоб CRM запускалася разом із комп'ютером: Docker Desktop → **Settings** →
**General** → **Start Docker Desktop when you sign in**. Сервіси CRM
запускаються автоматично разом із Docker Desktop.

Резервну копію робіть щонайменше раз на тиждень і копіюйте файл із
`deploy/backups` у хмарне сховище або на зовнішній носій. Копію файлу `.env`
зберігайте разом із ним.

Доступ для колег у тій самій мережі та постійна робота на власному обладнанні
описані в [own-hardware.md](own-hardware.md).

## Варіант Б. На хостингу з панеллю Dokploy

CRM працює на орендованому сервері й доступна з інтернету за власною адресою.
Dokploy — безкоштовна панель керування, у якій усе робиться через браузер.
Деякі провайдери пропонують сервер із уже встановленим Dokploy; інструкція
наведена на прикладі Hostinger, де це робиться під час замовлення. В інших
провайдерів Dokploy встановлюється однією командою по SSH — це описано в
[server.md](server.md#dokploy).

### Що знадобиться

1. **Сервер** із попередньо встановленим Dokploy.
2. **Доменне ім'я** — адреса, за якою відкриватиметься CRM, наприклад
   `crm.назва-організації.org.ua`. Зручно придбати в того самого провайдера,
   де замовляється сервер: усе налаштовується в одному кабінеті.
3. **Менеджер паролів** для збереження облікових даних і двох секретів.

### Крок 1. Замовити сервер

У кабінеті Hostinger: **VPS** → оберіть тариф. Мінімальний (KVM 1: 1 процесор,
4 ГБ пам'яті) достатній для організації з кількома десятками користувачів.

Під час налаштування:

1. **Розташування:** дата-центр у Європі. Про вибір розташування —
   [hosting-providers.md](hosting-providers.md#розміщення-даних).
2. **Операційна система:** вкладка **OS with Panel** → **Ubuntu 24.04 with
   Dokploy**.
3. **Пароль root:** згенеруйте й збережіть у менеджері паролів. Для
   повсякденної роботи він не потрібен.

Після створення сервера в його картці буде вказана **IP-адреса** — чотири числа
через крапку, наприклад `185.12.34.56`.

Одразу ввімкніть у налаштуваннях сервера **резервні копії** (backups або
snapshots). Це захист від втрати всього сервера; у деяких тарифах опція входить
у вартість, в інших — платна.

### Крок 2. Придбати домен і спрямувати на сервер

1. У кабінеті провайдера придбайте доменне ім'я, якщо його ще немає.
2. Відкрийте керування DNS-записами домену (у Hostinger: **Домени** → домен →
   **DNS / Сервери імен**) і додайте запис:

   | Поле        | Значення                                           |
   | ----------- | -------------------------------------------------- |
   | Тип         | `A`                                                |
   | Ім'я / Host | `crm` (CRM відкриватиметься за адресою `crm.ваш-домен`) |
   | Значення    | IP-адреса сервера з кроку 1                        |
   | TTL         | залиште за замовчуванням                           |

Зміни набувають чинності протягом кількох хвилин, іноді до години. Решту кроків
можна виконувати одразу.

### Крок 3. Увійти в Dokploy

Відкрийте в браузері `http://IP-адреса-сервера:3000`. При першому вході Dokploy
запропонує створити обліковий запис адміністратора; збережіть дані в менеджері
паролів.

Рекомендовано одразу перевести панель на захищене з'єднання: **Settings** →
**Server** → **Server Domain**: `panel.ваш-домен` (для цього імені потрібен ще
один `A`-запис, як у кроці 2), **Let's Encrypt** → **Save**. Через хвилину
панель відкривається за адресою `https://panel.ваш-домен`.

### Крок 4. Підготувати секрети

Згенеруйте в менеджері паролів два різних пароля довжиною від 32 символів,
**лише з латинських літер і цифр**, без пробілів і спеціальних символів.
Збережіть їх під назвами «CRM — пароль бази даних» і «CRM — ключ підпису».

Без цих значень резервну копію неможливо відновити.

### Крок 5. Створити сервіс

1. **Projects** → **Create Project**. Назва: `CRM`. Відкрийте проєкт.
2. **Create Service** → **Compose**. Назва: `crm`. Відкрийте сервіс.
3. Вкладка **Provider** → **Git**:

   | Поле           | Значення                                                    |
   | -------------- | ----------------------------------------------------------- |
   | Repository URL | `https://github.com/uniia-ave-team/crm-with-ngos.git`       |
   | Branch         | `stable`                                                    |
   | Compose Path   | `deploy/docker-compose.dokploy.yml`                         |

   Натисніть **Save**.

4. Вкладка **Environment**. Вставте текст, замінивши значення на свої:

   ```
   DOMAIN=crm.ваш-домен.org.ua
   TZ=Europe/Kyiv
   POSTGRES_DB=crm
   POSTGRES_USER=crm
   POSTGRES_PASSWORD=перший-згенерований-пароль
   AUTH_SIGNING_KEY=другий-згенерований-пароль
   ```

   Натисніть **Save**.

5. Вкладка **Domains** → **Add Domain**. Створіть два записи:

   | Поле           | Перший запис          | Другий запис          |
   | -------------- | --------------------- | --------------------- |
   | Service Name   | `web`                 | `api`                 |
   | Host           | `crm.ваш-домен.org.ua` | `crm.ваш-домен.org.ua` |
   | Path           | `/`                   | `/api`                |
   | Container Port | `8080`                | `8080`                |
   | HTTPS          | увімкнено             | увімкнено             |
   | Certificate    | Let's Encrypt         | Let's Encrypt         |

   Інші параметри лишіть за замовчуванням.

6. Натисніть **Deploy** у верхній частині сторінки. Dokploy завантажить файли
   та образи й запустить сервіси; це триває кілька хвилин. Хід видно у вкладці
   **Deployments**; успішне завершення позначається станом **Done**.

### Крок 6. Перевірити

Відкрийте `https://crm.ваш-домен.org.ua`. Перший запит триває кілька секунд —
у цей час отримується сертифікат.

Якщо сторінка не відкривається через 10 хвилин:

- Перевірте, що DNS-запис із кроку 2 вказує на правильну IP-адресу. Зміни
  можуть поширюватися до години.
- У Dokploy відкрийте сервіс → **Deployments** → останнє розгортання →
  перегляньте журнал. Найпоширеніша причина — помилка у змінних: відсутнє
  значення або зайвий пробіл.
- Стан окремих контейнерів — вкладка **Logs**; оберіть сервіс зі списку.

### Далі

- **Резервні копії.** CRM щодня створює копію бази на сервері; резервні копії
  сервера в кабінеті провайдера (крок 1) зберігають її разом з усім сервером.
  Докладніше — [backups.md](backups.md).
- **Оновлення.** [upgrading.md](upgrading.md#рівень-1-dokploy).

Створіть issue в репозиторії з описом кроку, на якому виникла проблема, та
текстом помилки з вікна встановлення або журналу. Не вставляйте у issue
значення `POSTGRES_PASSWORD` та `AUTH_SIGNING_KEY`.
