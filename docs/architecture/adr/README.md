# Архітектурні рішення

Записи про рішення, які складно переглянути пізніше, з обґрунтуванням, чому
їх ухвалено. Запис створюється, коли рішення обмежує обидві команди, змінює дії
адміністратора інсталяції або мало альтернативи, що серйозно розглядалися.

Порядок: скопіювати [`template.md`](template.md), присвоїти наступний номер,
подати разом із pull request'ом, що реалізує рішення. Записи не редагуються
після ухвалення; переглянуте рішення оформлюється новим записом, а попередній
позначається заміненим.

Назви файлів — англійською, вміст — українською.

## Відкриті рішення

- **Ліцензія.** AGPL-3.0 (похідні сервіси зобов'язані публікувати код) або
  Apache-2.0 / MIT (без обмежень на використання). До появи файлу `LICENSE`
  код не має дозволу на використання.
- **Модель автентифікації.** Сесії, які видає API, або зовнішній постачальник
  ідентичності; потреба в SSO для інсталяцій.
- **Мультитенантність.** Одна організація на інсталяцію або кілька в одній
  базі. Зміна після запуску коштує дорого.
- **Мобільний клієнт.** Збірка вебклієнта через Capacitor створює другого
  споживача API з окремим циклом випуску й потребує політики сумісності —
  див. [ADR 0001](0001-monorepo-and-lockstep-versioning.md#мобільний-клієнт).
- **Платформа документації.** Генератор сайту документації та місце
  розміщення.
