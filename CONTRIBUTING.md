# Участь у проєкті

Проєкт розробляє внутрішня команда. **Зовнішні pull request'и до коду поки не
приймаються.** Код відкритий: його можна читати, розгортати, змінювати під
власні потреби та форкати.

## Що можна зробити зараз

**Повідомити про помилку або запропонувати можливість.** Створіть issue. У
повідомленні про помилку вкажіть версію (`CRM_VERSION` у `deploy/.env` або в
налаштуваннях панелі), спосіб розгортання та очікувану поведінку.

**Повідомити про проблему з розгортанням або оновленням.** Такі повідомлення
мають найвищий пріоритет: придатність для встановлення людиною без технічної
підготовки є основною вимогою до продукту.

**Виправити або доповнити документацію.** Зміни в `docs/` приймаються через
pull request.

## Зміна моделі участі

Коли проєкт відкриється для зовнішніх змін у коді, цей файл буде оновлено з
описом процесу.

## Для команди розробки

Робочі домовленості — гілки, коміти, зміна контракту, міграції бази — описані в
[docs/development.md](docs/development.md).
