# Участь у проєкті

Проєкт розробляє внутрішня команда. Зовнішні pull request'и до коду поки не
приймаються; повідомлення про помилки та пропозиції — через issues.

## Мова

| Що                                                     | Мова       |
| ------------------------------------------------------ | ---------- |
| Коміти, гілки, теги, назви й описи PR, коментарі в рецензіях | Англійська |
| Код, ідентифікатори, коментарі в коді, технічні логи   | Англійська |
| Документація (`docs/`, `README.md`, цей файл)          | Українська |
| Інтерфейс і повідомлення про помилки для користувача   | Українська |

## Гілки

`main` завжди придатна до релізу. Робочі гілки короткоживучі й відгалужуються
від `main`. Назва — `тип/короткий-опис` англійською:

```
feat/contact-import
fix/role-permissions-cache
chore/update-ef-core
```

## Коміти

Формат — [Conventional Commits](https://www.conventionalcommits.org)
англійською. Scope необов'язковий: `api`, `web`, `docs`, `ci`, `deps`.

```
feat(api): add CSV import for contacts
fix(web): keep pipeline filter after page reload
chore(deps): bump EF Core to 10.0.13
feat(api)!: rename Deal.amount to Deal.value
```

`!` або футер `BREAKING CHANGE:` позначає зміну, яка потребує дій від
адміністратора інсталяції (дані, конфігурація).

## Pull request'и

- Вливаються через **squash merge**: назва PR стає повідомленням коміту в
  `main`, тому вона теж має відповідати Conventional Commits.
- Розмір — придатний для рецензії за один підхід.
- Перед відкриттям PR: `just lint` і `just test`.

## Міграції бази

- Створення: `just migration-add НазваМіграції` (англійською, PascalCase).
- Міграції застосовуються автоматично під час запуску API.
- Лише вперед: down-міграції не використовуються.
- Спершу розширити, потім звузити: нова колонка додається й заповнюється,
  стара видаляється в наступному релізі.
