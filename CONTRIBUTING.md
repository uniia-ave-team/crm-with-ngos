# Участь у проєкті

Проєкт розробляє внутрішня команда. Зовнішні pull request'и до коду поки не
приймаються; повідомлення про помилки та пропозиції — через issues.

## Мова

| Що                                                     | Мова       |
| ------------------------------------------------------ | ---------- |
| Коміти, гілки, теги, назви й описи PR, коментарі в рецензіях | Англійська |
| Код, ідентифікатори, коментарі в коді, технічні логи   | Англійська |
| Документація (`docs/`, `README.md`, цей файл)          | Українська |
| Інтерфейс і повідомлення про помилки для користувача   | Українська |

## Гілки

`main` завжди придатна до релізу. Робочі гілки короткоживучі й відгалужуються
від `main`. Назва — `тип/короткий-опис` англійською:

```
feat/contact-import
fix/role-permissions-cache
chore/update-ef-core
```

## Коміти

Формат — [Conventional Commits](https://www.conventionalcommits.org)
англійською. Scope необов'язковий: `api`, `web`, `docs`, `ci`, `deps`
(`deps-dev` для dev-залежностей ставить Dependabot).

```
feat(api): add CSV import for contacts
fix(web): keep pipeline filter after page reload
chore(deps): bump EF Core to 10.0.13
feat(api)!: rename Deal.amount to Deal.value
```

`!` або футер `BREAKING CHANGE:` позначає зміну, яка потребує дій від
адміністратора інсталяції (дані, конфігурація).

## Pull request'и

- Вливаються через **squash merge**: назва PR стає повідомленням коміту в
  `main`, тому вона теж має відповідати Conventional Commits.
- Розмір — придатний для рецензії за один підхід.
- Перед відкриттям PR: `just lint` і `just test`; `just ci` виконує локально
  те саме, що CI для API і вебклієнта.

Обов'язкові перевірки для злиття:

- **`ci-ok`** — підсумок `ci.yml`. Запускаються лише джоби для змінених
  частин (API, вебклієнт, контракт); пропущена джоба не вважається
  помилкою.
- **`pr-title`** — назва PR відповідає Conventional Commits.

Ламкі зміни API (`oasdiff`) і знахідки Trivy та CodeQL злиття не блокують:
перші видно в підсумку джоби `api`, інші — у вкладці Security.
Dependabot щопонеділка відкриває згруповані PR з оновленнями залежностей.

## Зміна API

`packages/api-contract/openapi.json` — контракт між API і вебклієнтом. Він
генерується з коду .NET і комітиться, тому кожна зміна ендпоінта видна в diff
pull request'а.

1. Змінити ендпоінт в `apps/api`. Описи операцій і моделей беруться з
   XML-коментарів (`/// <summary>`).
2. Виконати `just contract`: оновлюються `openapi.json` і згенерований
   Angular-клієнт у `apps/web/src/app/api/generated`.
3. Оновити місця виклику у вебклієнті.
4. Закомітити `openapi.json`. Згенерований клієнт не комітиться: він
   створюється автоматично перед `npm start`, `npm run build` і тестами.

Ідентифікатор операції має вигляд `{Контролер}{Дія}`, наприклад
`UsersAssignRole`; з нього клієнт отримує назву функції. Перейменування
методу контролера змінює назву функції в клієнті.

`just ci` перевіряє, що закомічений `openapi.json` відповідає коду.

## Міграції бази

- Створення: `just migration-add НазваМіграції` (англійською, PascalCase).
- Міграції застосовуються автоматично під час запуску API.
- Лише вперед: down-міграції не використовуються.
- Спершу розширити, потім звузити: нова колонка додається й заповнюється,
  стара видаляється в наступному релізі.
